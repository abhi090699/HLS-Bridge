The hls_bridge_qos block aggregates TLP completion counts from AXI Bridge ports and forwards them to the HAL layer via the QoS TX interface.
Completion ordering is not required. DTI is an active source when KMAX_DTI_SUPPORT = 1, contributing via a dedicated SOP/EOP detection path. MSI is
an active source when KMAX_MSI_IF_SUPPORT = 1.

6.7.4 Detailed Description
Each QoS packet carries a completion count in tlp_qos_rx_tdata[12:0], a QOS_TYPE field (Request = 0 / Response = 1), a TLP_TYPE field (Posted
= 0 / Non-Posted = 1), and a TLP_STREAM index. A single port may issue packets with different QOS_TYPE / TLP_TYPE combinations. The 
hls_bridge_qos module accumulates counts into separate groups indexed by QOS_TYPE, TLP_TYPE, and TLP_STREAM.
The total number of counter groups depends on configuration:
NUM_TLP_STREAMS × 2 (TLP_TYPE) × 2 (QOS_TYPE) — default: 8 × 4 = 32 groups
Each counter group can receive contributions from the following sources:
AXI Bridge ports — depends on NUM_HLS_PORTS (n × AXI_bridge)
DTI — active when KMAX_DTI_SUPPORT = 1. Two hls_bridge_qos_dti_pck_enc instances handle the Posted (i_qos_dti_p, IS_POSTED=1) and Non-Posted
(i_qos_dti_np, IS_POSTED=0) channels independently. Their per-slot enables are OR'd in dti_counter_en_transpose and driven directly into 
hls_bridge_qos_counter.dti_en, bypassing the qos_counter_en_tab[] array used by AXI and MSI sources.
MSI — active when KMAX_MSI_IF_SUPPORT = 1; (see MSI QoS Source)
The hls_bridge_qos module accumulates counts from all active sources into the matching group counter. When a group is drained, the accumulated
value is latched into a one-cycle pipeline register and forwarded as a single QoS TX packet; the counter is then cleared. If a new count arrives on the
same cycle as the clear, the incoming value is stored as the new counter value — the previous value has already been latched for output.
The drain order (ascending rr_counter) is: P&REQ (slots 0–7) → NP&REQ (slots 8–15) → P&RESP (slots 16–23) → NP&RESP (slots 24–31), each
group spanning all TLP_STREAM indices.

Drain Mechanism
A free-running rr_counter advances one slot per clock cycle regardless of whether the current slot is non-zero. When the counter points to a non-zero
group:
The accumulated count is latched into a one-cycle pipeline register.
The latched value is forwarded as a QoS TX packet.
The group counter is cleared.
There is no backpressure and no busy-gating. Worst-case latency from count arrival to TX output is one full rr_counter sweep (COUNT_NUMBER cycles =
32 by default).
The maximum completion count a single source may send on tlp_qos_rx_tdata[12:0] in one clock cycle is 0x18 (24 decimal) — a system-level
protocol constraint that prevents 13-bit counter overflow. The worst-case service interval between consecutive drains of the same group is 
NUM_TLP_STREAMS × 4 = 32 cycles (default configuration).
With four active RX sources all targeting the same counter group in the same cycle, the maximum single-cycle accumulation is 0x60 (4 × 0x18 = 96
decimal). The QoS counter is 13 bits wide (DATA_SIZE = 13); there is no 0xFF ceiling — the 0x18 per-cycle protocol constraint is what prevents
overflow.

DTI QoS Source
When KMAX_DTI_SUPPORT = 1, the DTI path contributes to the same 32 counter groups as the AXI and MSI sources, using a separate counting
mechanism.
Two instances of hls_bridge_qos_dti_pck_enc detect completed TLP packets from the DTI HLS control bus:
Instance Parameter Counter groups enabled
i_qos_dti_p IS_POSTED = 1 P&REQ (slots 0–7) and P&RESP (slots 16–23)
i_qos_dti_np IS_POSTED = 0 NP&REQ (slots 8–15) and NP&RESP (slots 24–31)
Each instance examines SOP and EOP flags per TLP slot in the incoming HLS control bus. A packet is counted when a SOP and EOP coincide in the
same clock cycle. Spilled packets (SOP without EOP) are tracked across cycles; the spilled packet is counted when the deferred EOP arrives in a
subsequent cycle.
The per-slot enables from both instances are bitwise-OR'd in dti_counter_en_transpose to form dti_counter_en_2d[COUNT_NUMBER][KMAX_NUM_TLPS_PER_CLK:0],
which is driven into each hls_bridge_qos_counter instance via the dti_en port.
The dti_en bus is KMAX_NUM_TLPS_PER_CLK+1 bits wide: bits [K-1:0] correspond to normal TLP slots and bit [K] to the spilled-packet slot.
